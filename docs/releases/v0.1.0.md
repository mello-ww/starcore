# StarCore 0.1.0

The first stable release of StarCore: a self-hosted home server core with Mission Control on
the web and an Android app. Since the Alpha (0.1.0-alpha.1), every Satellite has moved to
its shared interface: each one describes its pages as data (UI contract 1.2) and both
clients draw them with the same generic renderers. No Satellite has client code of its own
any more. Report problems with **Copy build info** (Mission Control: Configuration > About;
Android: Settings > About).

## What's in it

- **Music** on its shared interface on both clients: home, search, Your Library, albums,
  artists, playlists, mixes, radio, lyrics, stats and offline downloads. It plays through one
  shared audio host per client, with gapless playback on Android and a sleep timer.
- **Photo** on its shared interface: the library, albums, the map, search, the shared viewer,
  imports into a folder you choose, and **phone backup** that runs in the background on
  Android with its own device credential.
- **Locked Folder** on its shared interface: browsing, moves, setup, PIN, encryption,
  location and recovery on both clients, and biometric unlock on Android.
- **File Explorer** on its shared interface, also its first file browser on Android: paged
  folders, a page for each file (preview, open, download, share), create, rename, delete and
  upload.
- **Status** with its declarative dashboard, and the **Docker** link Satellite.
- **Satellite icons** declared by each Satellite and drawn by both clients.
- Security: session tokens stored hashed (existing sign-ins carry over), the session cookie
  marked `Secure` behind an HTTPS proxy, Pillow 13 and the other dependency updates from the
  pre-release audit.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list.

## Install

**Android** - download `StarCore-0.1.0.apk` below and open it (allow installing from this
source). Check it against `StarCore-0.1.0.apk.sha256` if you like. It installs over the
Alpha's APK, which was signed with the same key. On first launch, enter your server's
address: a public host name is tried over HTTPS, a LAN address like `192.168.1.20:8090` over
HTTP.

**Server** - see `docs/deployment.md`, "Linux server (systemd)". A fresh install prints a
one-time setup code in its log (`journalctl -u starcore`); Mission Control asks for it when
you create the administrator account from another device.

Requirements: Python 3.13 (installed by `install.sh` through uv), FFmpeg and Pillow for video
and photo thumbnails, Android 7.0 (API 24) or later.

## Upgrading

From the Alpha on a Linux server: back up `/var/lib/starcore` and the `config.toml` files,
then `sudo bash deploy/linux/install.sh --update` and `sudo systemctl restart starcore`.
Stored sessions are converted to hashes on the first start. Install the new APK too: this
release's server and app are meant to be used together, and nothing is kept for older apps.
Details, backups and rollback: `docs/releasing.md`.

## Known limitations

- **Tested by automated tests, on an Android emulator and on Linux**, not yet on a range of
  physical phones. Background phone backup has not run on a real phone yet. iOS doesn't
  exist yet.
- **Single administrator account.** No additional users or roles.
- **Music and video streaming over HTTPS** are configured (unbuffered, long timeouts) but have
  not been verified end to end through a production proxy with large uploads.
- **One signing key.** Rolling the app back means uninstalling and reinstalling the older APK.
- **Locked Folder encryption is server-side**: it protects copies, backups and stolen disks,
  not a compromised server. Without a recovery key, an encrypted vault is lost if the server
  key is lost. Unlocks are in memory, so a restart locks every session.
- The Android app has no light theme.
- On Android 15+ devices that use 16 KB memory pages, Android shows a one-time "not 16 KB
  compatible" notice and runs the app in compatibility mode: React Native 0.73's native
  libraries predate 16 KB alignment. The app works; fixing it needs a React Native upgrade,
  as do the remaining npm advisories in the Android build tooling (see the roadmap's
  pre-release audit).
- Sign-in lockouts are kept in memory and reset when StarCore restarts.
- The Signal Bus and Space Mode are not implemented. Developer Mode only changes what is shown,
  never what is allowed.
- Some Python tests are skipped on Windows (permissions, symlinks, FFmpeg) and pass only on a
  system that supports them.
