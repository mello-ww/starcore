# StarCore 0.1.0-alpha.1

The first Alpha of StarCore: a self-hosted home server core with Mission Control on the web
and an Android app. This is a **pre-release** - a stable checkpoint to test and build on,
not a feature-complete 1.0. Expect rough edges; report them with **Copy build info**
(Mission Control: Configuration > About; Android: Settings > About).

## What's in it

- **Engine** with Satellites: **Music**, **Photo** (with phone backup), **Locked Folder**
  (encrypted vault inside Photos), **File Explorer**, **Status** and the **Docker** link
  Satellite.
- **Mission Control** in the browser, and the **Android app** for the same server.
- **Linux deployment**: an install script, a hardened systemd service and an nginx HTTPS site.
- Version and build information everywhere, from one `VERSION` file and Git.
- First-run setup protected by a one-time setup code; sign-in throttling per client behind
  HTTPS.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list.

## Install

**Android** - download `StarCore-0.1.0-alpha.1.apk` below and open it (allow installing from
this source). Check it against `StarCore-0.1.0-alpha.1.apk.sha256` if you like. On first
launch, enter your server's address: `starcore.example.com` is tried over HTTPS, a LAN
address like `192.168.1.20:8090` over HTTP.

> If you had a development build of the app (installed with `npm run android`), uninstall it
> first - Android won't replace it with this signed release. Uninstalling removes the app's
> saved servers and sign-ins, not anything on the server.

**Server** - see `docs/deployment.md`, "Linux server (systemd)". A fresh install prints a
one-time setup code in its log (`journalctl -u starcore`); Mission Control asks for it when
you create the administrator account from another device.

Requirements: Python 3.13 (installed by `install.sh` through uv), FFmpeg and Pillow for video
and photo thumbnails, Android 7.0 (API 24) or later.

## Upgrading

From the pre-release checkout on the Linux server: back up `/var/lib/starcore` and the
`config.toml` files, then `sudo bash deploy/linux/install.sh --update` and `sudo systemctl
restart starcore`. Nothing in this release changes stored data. Details, backups and
rollback: `docs/releasing.md`.

## Known limitations

- **Alpha quality.** Tested by automated tests, on an Android emulator and on one Linux
  server; not yet on a range of physical phones. iOS doesn't exist yet.
- **Single administrator account.** No additional users or roles.
- **Music and video streaming over HTTPS** are configured (unbuffered, long timeouts) but have
  not been played end to end through the production proxy yet; nor has an upload over 1 MB.
- **One signing key.** Updates install in place only over this release's signed APK. Rolling
  the app back means uninstalling and reinstalling the older APK.
- **Locked Folder encryption is server-side**: it protects copies, backups and stolen disks,
  not a compromised server. Without a recovery key, an encrypted vault is lost if the server
  key is lost. Unlocks are in memory, so a restart locks every session.
- The Android app has no light theme; some Music controls are text glyphs and may render as
  emoji on some phones; the Locked Folder location, encryption and recovery are managed from
  Mission Control only.
- On Android 15+ devices that use 16 KB memory pages, Android shows a one-time "not 16 KB
  compatible" notice and runs the app in compatibility mode: React Native 0.73's native
  libraries predate 16 KB alignment. The app works; fixing it needs a React Native upgrade.
- Sign-in lockouts are kept in memory and reset when StarCore restarts.
- The Signal Bus and Space Mode are not implemented. Developer Mode only changes what is shown,
  never what is allowed.
- Five Python tests are skipped on Windows (permissions, symlinks, FFmpeg) and pass only on
  a system that supports them.
